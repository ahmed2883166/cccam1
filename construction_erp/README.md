# نظام المقاولات (Construction ERP)

نظام محاسبة للشركات المقاولات، بالمعايير الدولية (IFRS كما تطبقه SOCPA في السعودية)، واجهة عربية من اليمين لليسار.

**الحالة: المرحلة 0 + المرحلة 1 + المرحلة 2 (المبيعات والمشتريات والتحصيل والسداد).** موجود الآن:
- تسجيل دخول بكلمات مرور مشفّرة (PBKDF2).
- دليل حسابات افتراضي مناسب للمقاولات (مستخلصات، محتجزات، أعمال تحت التنفيذ، مقاولين من الباطن، دفعات مقدمة).
- قيود يومية مع منع أي قيد غير متوازن، ومنع الترحيل في فترة مقفلة، ومنع القيد على حساب تجميعي.
- ميزان المراجعة وشجرة الحسابات.
- العملاء والموردين، وفواتير المبيعات والمشتريات (ضريبة 0% و15%) مع ترحيل وترقيم.
- إشعارات دائنة (مرتجع مبيعات) ومدينة (مرتجع مشتريات) بكميات جزئية، ومنع تجاوز الكمية المتاحة.
- سندات قبض وصرف، تسوية على فواتير، والباقي يُسجَّل دفعة مقدمة ويُسوّى لاحقًا من صفحة السند.
- الأرصدة المفتوحة والدفعات المقدمة غير المستخدمة.
- تقرير أعمار الديون (عملاء وموردين) على 4 شرائح: 0-30، 31-60، 61-90، أكثر من 90 يومًا.
- ملخص الإقرار الضريبي للفترة: ضريبة المخرجات والمدخلات بعد خصم الإشعارات.
- المشروعات (عقود مع العملاء بنسبة محتجز) والمستخلصات: الإنجاز التراكمي، الفرق عن آخر مستخلص، ضريبة 15%، المحتجز (1106)، ومنع تجاوز قيمة العقد.
- تحصيل المستخلصات (يقفل 1104) وإطلاق المحتجز (يقفل 1106) مع منع تجاوز المتبقي.
- القوائم المالية: المركز المالي وقائمة الدخل لفترة، مع فحص التوازن. أرباح الفترات السابقة بتتحسب من الحسابات المفتوحة لحد الآن (من غير قيود إقفال سنوي).
- اختبارات للقواعد المحاسبية والفواتير والسداد والتقارير والمستخلصات.

**لسه ما اتعملش:** الفوترة الإلكترونية لهيئة الزكاة (ZATCA: XML والـ QR والتوقيع والربط مع المنصة)، مراكز التكلفة، ربط المستخلصات بفواتير المبيعات (المستخلص بيترحّل مباشرة على 1104 مش على فاتورة، فعشان مايتحسبش مرتين لازم الشغل المستخلص ميتفوترش تاني)، قائمة التدفقات النقدية وقائمة التغيرات في حقوق الملكية، الداش بورد التفصيلي، المخزون، سجل المراجعة.

## الهجرات (Alembic)

الجداول بتتدار بالهجرات، مش بـ `create_all`. قبل أول تشغيل ولأي تغيير في النماذج:

```bash
alembic upgrade head                 # تطبيق الهجرات
alembic revision --autogenerate -m "وصف التغيير"   # إنشاء هجرة جديدة بعد تعديل النماذج
```

الهجرة الأولى (`initial schema`) مولّدة من النماذج الحالية. اتجربت على PostgreSQL 16 (upgrade وdowngrade وcheck والـ seed والـ smoke test للويب)، وكمان على SQLite للاختبارات.

## التشغيل بـ Docker

```bash
export CERP_SECRET_KEY="$(python -c 'import secrets;print(secrets.token_urlsafe(48))')"
docker compose up -d --build
```

ولإنشاء الشركة ودليل الحسابات والمستخدم الأولي (لازم تمرر كلمة المرور):

```bash
docker compose exec -e CERP_ADMIN_PASSWORD='كلمة-مرور-قوية' web python -m app.seed
```

افتح `http://localhost:8000`.

## التشغيل محليًا للتطوير

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export CERP_DATABASE_URL="sqlite:///./dev.db"   # للتجربة السريعة فقط
export CERP_ADMIN_PASSWORD='كلمة-مرور-قوية'
python -m app.seed
uvicorn app.main:app --reload
```

## الاختبارات

```bash
pytest -q
```

## قواعد عامة لازم تفضل ثابتة

- كل قيد يمر على `app/accounting.py` (`post_entry`) فقط، ومحدش يكتب في جداول القيود مباشرة.
- المبالغ بـ `Decimal` ومقربة لقرشين، ومفيش `float` في أي حساب مالي.
- القيد المرحّل مش بيتعدل ولا بيتحذف؛ التصحيح بقيد عكسي.
- قبل الاستخدام الفعلي: غيّر `CERP_SECRET_KEY` وكلمة مرور المدير، وفعّل HTTPS، واختبر النسخ الاحتياطي.
